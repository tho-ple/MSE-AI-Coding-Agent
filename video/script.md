# Narration

## Scene 0 — Title

```text
This is my Stage 2 delivery: a coding harness in Python, built on LangGraph. It handles a feature across modules, keeps context bounded, and saves work safely. The voice is generated by a text to speech model.
```

## Scene 1 — Requirements and where they live

```text
Each required part has its own module. Navigation, context, the task loop, and sessions are separate. The harness itself runs the test, lint and build checks. The command line interface only calls the core.
```

## Scene 2 — Architecture

```text
A user picks an allowed project and starts a task from the command line. The app module starts, resumes, cancels and reviews sessions. The controller is a LangGraph state machine. Its tools reach the navigation index, a disposable workspace, and the sandbox. The model can be local Ollama or any Open A I compatible endpoint.
```

## Scene 3 — Navigation

```text
The repository index parses every Python file of the copy. Nothing is imported or executed. The model can find a symbol, find its references, list a module's dependencies, and get a compact repository map. Read only git tools show the baseline commit and the diff.
```

## Scene 4 — Bounded context

```text
Each model request has three layers. First, the trusted part: system rules and the task brief, with scope and acceptance criteria. It is never shortened. Second, ranked repository files, a map, and excerpts. Third, the history. When the request exceeds the documented size limit, old tool output is cut, and the oldest turns become a short harness summary. Repository text and tool output stay marked as untrusted.
```

## Scene 5 — Edit–test–fix loop

```text
The agent asks the model, and the act node runs its tool calls. After finish, the harness runs all checks. If a check failed, rounds are left, and the change made progress, the failed output goes back to the model. The loop stops on success, an unavailable check, used up rounds, or no progress. A failed or unavailable check is never shown as passed.
```

## Scene 6 — Cancel and safe resume

```text
This is a real session, cancelled during a model request. The harness returned at once, and the late reply was discarded. Every action is journaled before and after it runs. On resume, the used limits are kept. Permissions and the working copy fingerprint, including the harness's own edits, are checked again. On a mismatch or an uncertain action, the session pauses. It never replays it.
```

## Scene 7 — Protecting the environment

```text
The agent works on a disposable copy without a remote, so push and merge are impossible. Code runs in a container without network and with dropped capabilities. The acceptance checks are mounted read only. The API key never reaches executed code.
```

## Scene 8 — The feature and its acceptance check

```text
The target is the Cosmic Python allocation service at a pinned commit. The feature adds a deallocate command, with an error for lines that are not allocated. It touches three interacting modules, which the task does not name. On the starting code, five of six feature tests fail for the expected reason.
```

## Scene 9 — Real model run: `harness review`

```text
Here is the review of the real run with Qwen three point six on the F H endpoint. The model changed three modules and added four unit tests. All six harness checks passed, in twenty eight actions and about seventy five seconds. There was no manual help during the run. I wrote the task, the allowed changes and the checks beforehand.
```

## Scene 10 — Tests

```text
Every requirement has automated tests, and the Stage 1 tests still pass. The fix loop is tested with scripted model replies. The whole suite runs without a model, an API key, or a network. Thanks for watching.
```
